# CLAUDE.md

Read `docs/CONTEXT.md` first — it is the single-file digest of this whole project. This file
only holds commands and conventions.

## No-guessing rule

Never invent Midnight Network APIs, Compact syntax, package versions, or Docker image tags.
Every non-obvious fact already used in this repo is sourced in `docs/DECISIONS.md` — extend
that file, don't bypass it, when you add a new dependency on an external API.

## Commands

| Command | Does |
|---|---|
| `npm run bootstrap` | Verify Node/Docker, install the Compact compiler, `npm ci`, seed `.env` |
| `npm run compile:contracts` | Compile `packages/contracts/src/ballot.compact` to `managed/` |
| `npm run build` | Compile contracts, then build shared → server → client |
| `npm run dev:server` / `dev:client` | Run one package in watch mode |
| `npm run lint` / `typecheck` / `test` | Across all workspaces |
| `npm run docker:up` / `docker:down` / `docker:build` / `docker:logs` | Compose lifecycle |
| `npm run deploy:contract` / `create:poll` / `register:voter` / `read:tally` | CLI scripts in `scripts/` |

## Conventions

- TypeScript strict everywhere; no unexplained `any`.
- Workspaces: `packages/{contracts,shared,server,client}`, npm workspaces, Node 22+.
- `packages/shared` is the only place chain config, zod schemas, and the `ballot-client`
  contract wrapper are defined — both server and client import from it, never duplicate.
- Privacy invariant: nothing under `packages/server` may import a voter secret, witness, or
  Merkle path tied to a specific voter. Voter proving is client/wallet-side only. If you find
  yourself passing a secret to a server route, stop — that's the bug, not a missing feature.
- Docs live one-fact-one-file; if you're about to restate something from `docs/ARCHITECTURE.md`
  or `docs/CONTRACT_SPEC.md` elsewhere, link to it instead.
- Compiled ZK artifacts (`packages/contracts/managed/`, `packages/client/public/zk/`) are
  gitignored and regenerated by `npm run compile:contracts`; don't hand-edit or commit them.
